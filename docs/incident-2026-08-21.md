# 事故記録: job_runner.py の後半消失（2026-08-21）

## 何が起きたか

`backend/app/services/job_runner.py` の後半（関数定義13個）を消した。原因は私の編集操作。

解析ブロック（楽曲構造・ドラム）を追記する際、Python でこう書いた:

```python
old = s[s.index("    # ── 移動量バジェット(帯域別エネルギー→…"):]   # ← 指定位置から末尾まで
new = '''...新しい解析ブロック...'''
s = s.replace(old, new)
```

`old` が **「指定位置からファイル末尾まで」** になっており、置換によって
`_analyze_audio` 以降のすべてが新ブロックで上書きされた。

発覚は約8時間後。夜間生成ジョブ 3528 が
`name '_register_asset' is not defined` で失敗して初めて気づいた。

## 被害

失われた関数（13個）:

`_register_asset` `_analyze_video` `_create_proxy` `_separate_vocals` `_vlm_review`
`_decompose_character` `_puppet_clip` `_render_motion_graphics` `_render_orbit3d`
`_generate_3d` `_generate_video_3dcam` `_interpolate` `_cutout`

このうち `_register_asset` は**全生成ジョブが結果を保存するときに通る**ため、
画像・動画・音楽の生成がすべて機能停止していた。

## 復旧

git 管理外・バックアップ無し・`.pyc` も破壊後のものだったため、
**Claude Code の会話ログ（`~/.claude/projects/.../*.jsonl`）から復元**した。
過去の Read 結果に行番号つきでソースが残っていたため、それを抽出して戻した。

| 状態 | 関数 |
|---|---|
| **完全復元（8個）** | `_register_asset` `_create_proxy` `_separate_vocals` `_decompose_character` `_render_orbit3d` `_generate_3d` `_generate_video_3dcam` `_cutout` |
| **未復元（5個）** | `_analyze_video` `_vlm_review` `_puppet_clip` `_render_motion_graphics` `_interpolate` |

未復元の5個は、ログ上の断片が不完全で構文が通らなかった。
**推測で書き足すと動いているように見えて中身が違う**という最悪の状態になるため、
明示的に `RuntimeError` を投げるスタブにしてある。該当ジョブ種別は使えない:

- `analyze_video`（動画のシーン検出・モーション解析）
- `vlm_review`（VLMによる映像レビュー）
- `puppet_clip`（パペット合成）
- `render_motion_graphics`（MG書き出し）
- `interpolate`（フレーム補間）

映像生成・書き出し・音声解析は復旧済みで、AniPAFE2026 の制作は継続できる。

## 二次被害

- 復元コード追記時に、ヒアドキュメントの終端文字列 `PYEOF` が本文へ混入し、
  バックエンドが `NameError: name 'PYEOF' is not defined` で起動不能になった（除去済み）
- 復旧作業中の `--reload` でジョブ 3529 / 3530 が中断（再投入済み）

## 再発防止

1. **ファイル末尾までを含む置換をしない。** 範囲置換は必ず「開始と終了の両方」を
   文字列で指定する。`s[s.index(x):]` は使わない
2. **追記は `Edit` ツールを使う。** `>>` やヒアドキュメントでのコード追記は
   終端文字列の混入事故を起こす
3. **backend/ を触る前にコピーを取る。** git 管理外なので他に戻す手段が無い
4. 大きな編集の後は `python -c "import <module>"` まで確認する。
   `ast.parse` は構文しか見ず、今回の `PYEOF` 混入は素通りした
