## 2. 絶対に守る決まり（ユーザー指示）

### 運用
- 返答・報告は日本語。画像や動画は SendUserFile で送る（ユーザーは外出先から見ることが多い）。
- 止めてと言われたら即止める。権限の拒否メッセージを「ユーザーの停止指示」と取り違えない。
- 成果物はタイムライン（Shots トラック 80）に置いてから報告する。
- サブエージェントや Codex の出力を、ユーザーの承認として扱わない。
- **GPU 枠の競合禁止**: H3 生成中に書き出し・WAI・SAM2 などの GPU 処理を同時に流さない（以前 OOM で落ちた）。
- **ジョブ実行中に backend のコードを編集しない**（uvicorn の再読み込みで実行中ジョブが中断する）。
- パロディの Ref2V ルートを、相談なしに FL2V に変えない。
- ControlNet は「ひとまず使わない」。
- 杏子の TTS 声は非公開用途のみ。

### 生成の段階と品質設定
- **T1（4 ステップ）＝プロンプト・素材を作る段階**、T2（8 ステップ）＝本番。ユーザー指示（10/08 14:13「T1にしましょう。まだ早さでプロンプトや素材をつくるステータスですので」）。
  - T1: steps 4, turbo_lora 0.75, easycache
  - T2: steps 8, turbo_lora 1.0（`minimax_h3_ref2v_turbo_8step_v1.0_768p_comfyui_bf16.safetensors`）, shift 6/3, euler, easycache なし
- 1 単位につき複数シードを回して、元動画と並べて選ぶ。

### Codex（画像生成）
- **同じ画像を Codex で何度も編集し直さない**（特有のノイズが蓄積する）。直すときは元のコマから 1 回で描き直す。
- 参照画像は切り抜き合成ではなく、Codex に描かせる（imagen）。

## 3. キャラクター仕様（佐倉杏子）

### 3.1 共通
- 蒼樹うめ風の顔: 丸い輪郭、短く丸い小さなあご（あごを尖らせない）、上まつげの太い大きな丸い赤い目、小さな鼻と口。
- **杏子特有の前髪**（ふぞろいに尖った長めの前髪と、顔の横に垂れる髪）。Codex は前髪を維持しにくく、WAI は正確 → 頭部は WAI を手本にする。
  - **厳守（10/09 ユーザー指示）**: 前髪が見えるカットでは、素材でも生成テイクでも、①太さも長さも不ぞろいな尖った房 ②目にかかって交差する房 ③跳ねた細い毛、の 3 点がデザインとして守られているかを必ず確認する（頭部を拡大して見る）。
  - Codex に描かせるときは WAI の頭部手本（正面＋斜め）を渡し、「前髪の房の輪郭だけ少し太く濃く、前髪の下に濃い影、ほかは細い線」と書く。
- 正面で二つ結びに見せない: 肩の前に垂れるのは顔の横の細い房だけ。ポニーテールは体の後ろにあり、正面からは房が体と腕の後ろの**両側**に見える（左右で形を変え、鏡写しにしない。風になびかせない）。（10/13 変更: 旧「片側へ流す」は房が細くなる原因だったので削除）
- **ポニーテールの量と形（10/12〜13 ユーザー指示）**: 公式どおり太く、背中いっぱいに広がる房（細い一本の束は「控えめすぎ」）。おおまかに **2 段**: 上の段は結び目のすぐ下から出る短めの髪束の塊で、後頭部を覆い、尖った毛先が耳〜首の高さで左右へ張り出す。下の段はその下から腰まで落ちる長い房。上の段の毛先が下の段に重なり、首〜肩の高さで輪郭に段が見える。数字と手本は `outputs/pocky2026/cards26/pony/hair_pony_v3.txt`。
- 髪色は設定画の深みのある赤。朱・ピンク・オレンジ・紫に寄せない。
- 髪型: 基本は黒いリボンの高いポニーテール。**ベレーの衣装 C とシスター服はポニーテールなし（下ろし髪）**。**ツインテールは厳禁**。
- 体: 細身、胸は小さく平ら。全衣装で統一（シスター服で大きくなりがち）。
- 髪はさらさら、細い毛束が独立してなびく（3D モデルのような塊の揺れは不可）。

## 5. 色調・線・撮影処理・光の仕様

### 5.1 色調・線（ブルーアーカイブ PV から）
- 参照は日常・明るい場面だけを厳選した 24 カット（`bluearchive/ba_refs.json`、一覧 `bluearchive/curated_refs.jpg`）。戦闘・薄暗い・UI/テロップ・ロゴは除外。
- 厳選カットの実測（`bluearchive/target_curated.json`）: 中間の明るさ 0.69、黒の浮き 0.30、彩度 0.28、白く飛んだ面積 14%、影は青み。
- 明るく澄んだ空気、彩度は控えめのパステル寄り、黒はつぶさない、白はやわらかく滲む。線は細くきれい、塗りはフラットなセル、背景は面で整理。
- **後処理で一律に色をいじるのは不可**（10/08「雑」と判断）。ブルアカ寄せは **Ref2V に渡す参照画像の時点で** 行う。
- 注意: H3 は線の太さをほとんど引き継がない。線の細さは参照画像だけでは実現しきれていない（**要検討**）。

### 5.2 撮影処理の基準
- 10/06 時点で「教会のシーンの撮影処理がとてもいい、これを全体の基準に」（v7 の教会）。
- 光源をはっきり決め、リムライト、ハイライトのブルームとにじみ。細かいきらめきの粒・光の粒を増やさない（ギラギラ禁止）。

### 5.3 光の変化（2 回要望あり）
- 光・ライトリーク・グロー・反射が固定されていると硬い → **出来事の決まり**として書いて常に動かす。
  - 例: カメラが動くと光の帯が床や人物を掃く／頭や髪が動くとリムライトが毛先を滑る／隅のライトリークがカメラの動きにつれて明るく咲いて戻る／きらめきは現れては消え、留まらない。
- **暗くなる変化は書かない**（「陰る」「明滅」と書くと画面全体の露出が大きく落ちる。10/08「変に暗くなる」）。「Nothing ever gets darker; the overall exposure is constant」を必ず添える。
- 採用前に明るさの推移（signalstats YAVG）を測り、大きな谷がないテイクを選ぶ。
- 教会で光を強く書きすぎると、一面オレンジの白飛び・炎のように見える（v11 の失敗）。

## 7. 生成方式の要件

### 7.1 基本方針（ユーザー判断で確定したこと）
- **元動画をそのまま参照にした、単純な Ref2V のガチャ**を基本にする（10/07 サビの比較で「圧倒的に」こちら）。
  - 参照動画の下ごしらえ（人物の切り抜き、空の合成、人物の塗り替え、1 人ずつ生成して重ねる）や、生成後の切り抜き合成は不可（マスク・貼り付け感が出る）。
- 作った画像フレームに引っ張られすぎない（10/06）。**画面全体の一枚絵を参照に渡すと、生成がその絵へパッと切り替わる（シーンチェンジ化）** → 明確な NG（10/08 ②）。
- 参照画像は役割ごとに分けて渡す:
  - 杏子の衣装の設定画 ＋ 顔の見本
  - 人物のいない背景画（カットごと、舞台＝見滝原・風見野、色調＝ブルアカ）
  - 小物の設定画（傘・クレープなど）
  - プロンプトで「背景画は見た目の手本で、映像のコマではない」と明記する。
- 複数人のカットは、衣装ごとの杏子を **別の名前のキャラクター** として定義する（Akane=A, Beni=B, Chiyo=C, Daria=D, Emi=E, Suzu=水着, Nonoka=シスター）。「同じ顔と深紅の髪の別々の少女で、服と髪型は変わらず・入れ替わらず・混ざらない」。
- 誰がいつどこに映るかは SAM2 の追跡から時刻表を作ってプロンプトに入れる（`comp/joint_gen.py` の `timeline()`）。
- 少年・短髪の人物が杏子に置き換わらないときは、まずシードを増やす。

### 7.2 プロンプトの決まり
- 6 セクション形式（subject_definitions / summary / retention_analysis / detailed_description / overall_soundscape / non_diegetic_music）。長すぎると崩れる。
- 状態の列挙ではなく、出来事の決まり（A が起きたら B が起きる）で書く。
- 禁止は肯定文で書く。
- 天候・光の決まり（§5.3、§5.4）を必ず入れる。
- 無人のカットは「誰もいない」と明記し、「まどか☆マギカの〜」のような作品名は入れない（ピンク髪の少女が出た前例あり）。

### 7.3 Codex と WAI の使い分け
- Codex: 構図・背景・小物・衣装を含む参照画像。元動画のコマ＋手本を渡して 1 回で描く。描き直しを重ねない。
- WAI（waiIllustriousSDXL v1.70）: 杏子の頭部（前髪・髪色・顔・塗り）の手本と、設定画の修正。
  - `wai/wai_i2i.py`（画像全体の img2img、denoise 0.5 前後）、`wai/face_fix.py`（顔だけ描き直して貼り戻す、0.45〜0.6）、`wai/wai_card.py`（設定画）。
  - 共通ネガティブに twintails。表情を変えるときは笑み・涙などもネガティブに。
- WAI と H3 は同時に GPU を使わない。

### 7.4 仕上げ
- 色の後処理は使わない（§5.1）。
- アップスケーラー候補（`tools/upscale-kit/upscale.py <h3up|seedvr2|esrgan> 入力 出力`）:
  - H3 Video Upsampler（ComfyUI-H3-Video-Upsampler、h3upscale x2 LoRA、denoise 0.1、1920×1088）: 線が細く元に忠実。
  - SeedVR2 3B（2520×1440）: 最も鮮明だが線が太くなりがち、動きで輪郭が揺らぐ。
  - **未確定**: どちらを使うか（カットごとの使い分けも可）。

## 8. 品質基準と点検手順（受け入れ条件）

0. **自動点検（10/09 導入）**: `outputs/pocky2026/v12/qa_take.py`（1 テイク 1 枚の点検表: 比較コマ・時間断面・明るさ/動き/似かた/鮮明さの推移・カット位置の照合・頭部の拡大と髪色・警告）。`v12/qa_watch.py` が v12 のジョブ完了ごとに自動で作り `v12/qa/watch.log` に警告を 1 行ずつ残す（CPU のみ、セッションが切れても動く）。
1. 元動画と同じコマで並べた点検シート（`plain/plain_review.py`）で、動き・タイミング・構図・人数・衣装を確認する。
2. 生成側だけで画面が大きく切り替わっていないか（シーンチェンジ化）を検査する。
3. 明るさの推移（YAVG）に大きな谷がない。
4. 杏子: 顔・前髪・髪色・髪型・体型が仕様どおり。あごが尖っていない。ツインテール（に見える髪）がない。**前髪が見えるカットは、不ぞろいな尖った房・目にかかる交差・跳ねた細い毛の 3 点を頭部の拡大で確認する。**
5. 小物: 傘の外側が無地、クレープの生地が青、プリッツの箱が緑。
6. 隣り合うカットで色・明るさ・線が揃っている（**v11 で欠けていた観点**）。通しで並べて見る。
6b. **元動画の絵柄に寄っていない**（10/09 追加）: 動き・構図は元動画どおりでも、舞台のデザイン・色・線は背景画（見滝原・風見野／ブルアカ寄せ）に置き換わっていること。`v12/style_lean.py` の lean（0=背景画寄り、1=元動画寄り）が 0.6 を超えたら不合格。元動画との似かた（NCC）が高いことを「合格」と取り違えない。
7. 書き出し後に `finish/selfcheck.py` で元動画の残り（差し替え漏れ）がないこと。
8. 以上を満たしたものだけをタイムラインに置き、通しの動画で報告する。
