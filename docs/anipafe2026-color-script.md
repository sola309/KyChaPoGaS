# AniPAFE2026 カラースクリプト（2026-08-20 制定）

「カットごとに雰囲気が統一されていない」問題への根本対処。
実写・アニメの実制作では 色彩設計の色指定表 → カラースクリプト → **撮影が全カットへ統一処理**
という3段で画面が揃う。本プロジェクトにはこの層が一つも無く、モデル任せの
文章指定（LOOK基盤）だけで色を出していた。文章はシードごとに解釈が揺れるため、
**同一ブロック内でも明度0.17→0.24→0.28→0.02、色相17→183→151→180と暴れていた**（実測）。

原則: **色はプロンプトで「狙い」、撮影パスで「揃える」。** プロンプトだけで揃えようとしない。

### 赤の規則（最重要）
**赤はモチーフ専用の帯域**（糸・リボン・ソウルジェム・眼）。環境光・背景・装飾には使わない。
これにより赤が画面に現れた瞬間、それ自体が「因果」を意味するようになる。
C44-54で赤の面積が増えること自体が物語の進行を語る。

## 共通撮影パス（決定論・全カット一律）

モデル出力に依存しない統一層。プレビューと書き出しで**同一の**チェーンを適用する
（タイムライン表示と最終レンダのズレは禁止事項）。

```
1. 前ぼかし 0.3-0.6px      … AI特有のマイクロシャープを均す
2. ブロック別トリムLUT      … 上表の基調へ寄せる(強くしない。狙いはプロンプト側)
3. 黒締め (リフト微降下)     … 全編共通
4. フィルムグレイン 8-12%   … 全編共通・同一パターン
5. ビネット 弱              … 回想ブロックのみ強
```

## QA基準（「要素があるか」から「一本の映画に見えるか」へ）

カット単体での合格判定を廃止。出荷判定は必ず:
1. **隣接3連ストリップ** — 前後のカットと並べて1枚で目視。単体シートでの判定禁止
2. **ブロック窓チェック** — 明度・色相・黒占有が上表の窓に入っているか(数値は補助)
3. **参照比較** — 叛逆本編の静止画と並べて質感が負けていないか
要素チェックリスト(ワイプが出た/文字が読める等)は前提条件であって合格基準ではない。
