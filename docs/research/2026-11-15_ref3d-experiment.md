# 3D の手本で H3 の緩急とカメラをどこまで縛れるか(REF3D 実験、2026-11-15)

簡素な 3D 映像(comp-kit)を手本にして MiniMax H3 の T1(1344×768・24fps・124 コマ・4 段 Turbo)を 38 本作り、手本との時刻のずれを feel-kit で測った。衣装はポッキー2026 の承認済みの設定画。

## 結論(先に)

| 用途 | 向く方式 | 根拠(下の表) |
|---|---|---|
| 体の速い動きを拍に合わせて止める(腕) | **Fun ControlNet に骨(1.0)、または 深度 0.3 + 骨 0.7**。設定画は Picture | 動き出し・止まりが手本と同じコマ(ずれ 0〜+1、止まるコマの差 平均 0.8)。止めの残り 1% 前後 |
| カメラの速い振りを拍で止める | **Ref2V に手本 A(素体モデル)か B(灰色人形)** | 止まるコマの差 平均 0.8〜1.2、止まったあとの流れ 3px/コマ。ControlNet は 2〜5 コマ行き過ぎる |
| 回りこみ(カメラ + 後ろ姿) | **Ref2V A / B** | 相関 0.93、止まり 0〜+3 コマ。ControlNet 両方は +5 コマ |
| 衣装を大きく替える | どれでも可(A でも元の服は残らなかった) | 星柄 B(広がるスカート・ケープ)は 34 本、見た範囲で設定画どおり |

- 3 案の比べ(Ref2V の `<Video 1>` に渡したとき): **A(素体モデル)≒ B(灰色人形)> C(棒人形)**。C はカメラの止まりが甘い(止まったあとの流れ 9px/コマ、止まるコマの差 2.0)。体の動きの時刻は 3 案とも同じ(1〜2 コマ先走る)。
- A の弱み: 設定画に無い向き(パーカーは正面の絵しか無い)では、**手本の 3D モデルの後ろ姿がそのまま出た**(c2_M1A_P_s1。crops/crop_c2_f84.jpg の右端)。設定画に後ろ姿があれば出なかった(星柄 B)。
- Ref2V は 3 案とも、手本の**背景(箱・柵・床の影)をほぼそのまま写す**。ControlNet は背景を自分で描く(深度なら箱と柵の位置は残る。骨だけだと背景はカメラについてこない)。
- 確からしさ: 1 条件につきシード 2 個(対照は 1 個)。傾向は 2 シードでそろったが、数値の差 0.1 以下は誤差の内と見る。T1 だけ(T3 は未実施)。

## 作り方

- 手本(project 35 の comp 426〜440、asset 11164〜11178): `guides.py`。同じカメラ・同じキーで見た目だけ 5 種。
  A = VRM(asset 11160、私服パーカー)/ B = 顔のない灰色マネキン(髪なし)/ C = 棒人形 / 深度(B と舞台、近い = 白)/ OpenPose 形式の骨(黒い背景)。
  深度と骨は 3D から直接描いた(前処理モデルなし)。comp-kit に追加: mesh の `material.type: "depth"`(`near` `far`)、マネキンの `style: "openpose"`(`face_points` `line_width`)。
- カット(拍 = 9.6 コマ。150 BPM の格子): 1「腕」右腕を outCirc 7 コマで振り上げ → 拍 4(38 コマ目)で止め → 20 コマ止め → 拍 6 で 6 コマで下ろす。拍 8・10 で両腕も同じ。カメラ固定。
  2「カメラ」人物は静止。カメラが 19 コマかけて加速し続け(inCubic / inQuart)、拍 4・8・12 で止まる(80°・140°・140°)。
  3「回りこみ」右手を腰に当てた後ろ姿。ゆっくり流れ → 拍 4 から 39 コマ加速して拍 8 で止まり、10 コマで落ち着く。
  **61 コマにはできなかった**: バックエンドの `h3_snap_length` が 124 コマ未満を 124 に上げる(H3 の学習域の下限)。そこで 124 コマに出来事を 2〜3 回入れた。
- 生成: `h3.py`。アプリのジョブ `generate_video_i2v`(model `minimax-h3-ref`、steps 4・turbo_lora 0.75・easycache・scheduler beta・ref_image_size max)を project 35 に 1 本ずつ。
  M1 = Ref2V(`ref_video_asset_ids` に手本、ぼかしなし)。M2 = `fun_controls`(バックエンドに実装済みの `MiniMaxH3FunControlNetApply`。**設定画の Picture と同時に使えた**。参照動画は渡していない)。
  文は 2,000 字前後、6 セクション、動きは「何秒に何が起きて止まる」の因果だけ。衣装は「Picture のとおり」とだけ書いた。
- 衣装: 星柄 B = 正面 8577・真後ろ 8578・斜め後ろ 8579(輪郭が大きく違う物)。パーカー = 6673(手本 A に近い物。正面の絵だけ)。顔の見本 6674。シード 20261115・20261116。
- 測り方: `measure.py`(feel-kit の `motion_feat.py` の 動きの量 = mag × √area)。手本は B(灰色人形)。手本 A・C を同じ物差しで B と比べると相関 0.97〜1.00・止まり 0 コマ(物差しの確かさ)。
- 音: 完成版(さくら)の 2172 コマ目(60fps、小節の頭)から 5.2 秒。拍は feel-kit の audio_feat(beat_this)の結果。実際の拍は 9.72 コマ(24fps)なので、比較動画の音は 1.0125 倍速にして 9.6 コマの格子に合わせた。H3 には音を渡していない。

## 数値(方式ごと。衣装 B = 星柄、P = パーカー)

- 相関 = 速さの曲線の相関(124 コマ、ずらしなし)。3 コマならし = 2 コマ打ち(1 コマおきに止まる作画)の影響を外した物。
- 最良のずれ = 相関が最大になるずらし(負 = 出力が先走る、正 = 遅れる)。
- 止まるコマのずれ = 速い出来事のあと動きが山の 15% を下回るコマの、手本との差の絶対値の平均。( ) = 測れなかった数 / 出来事の数(背景や髪が動き続けて下回らなかった)。
- 山の高さの比 = 出力の山 ÷ 手本の山。**カット 2・3 では手本の速い振りを測定が追い切れず手本の山が低く出るので、1 を超えても「出力が速すぎる」ではない**。
- 止めの残り = 止めの区間の動きの平均 ÷ 手本の山(%)。手本は 0。
- カメラ止まり後の流れ = 止まって 2〜8 コマの画面全体の流れ(px/コマ)。カット 3 の手本は 6.0(落ち着くまでの 10 コマを含む)、カット 2 の手本は 0。

### 読み取り

- **腕(カット 1)**: Ref2V は 3 案とも 1〜2 コマ先走る(メモリの h3-ref2v-timing-lead と同じ癖)。ずらせば相関 0.76〜0.83 で形は合っている。ControlNet の骨 1.0 と「深度 0.3 + 骨 0.7」はずれ 0〜+1 コマ、止まるコマの差 0.8 前後で、**いちばん拍に乗る**。深度 1.0 だけはシード 2 で 1 回目の止まりが 11 コマ遅れた。強さ 0.6 は深度も骨も崩れる(相関 0.5〜0.57、止めの残り 4〜7%)。
- ControlNet の出力は腕が **2 コマ打ち**になった(動いているコマの 3〜4 割が前後より止まっている)。アニメらしい止め方で、止まりは鋭い。Ref2V は 1 コマ打ちで、髪・スカート・雲が止めの間も動く(止めの残り 3〜7%)。
- 山の高さの比がどれも 0.6〜0.8 なのは、黒い細い袖の動きを測定が拾いにくい分も入っている。動きが小さいという意味ではない(連続コマのシートで腕は手本と同じ角度まで上がっている)。
- **カメラ(カット 2)**: Ref2V の A・B は止まるコマの差 1 コマ前後・止まったあと 3px/コマ。C(棒人形)は 1 回目の止まりで 5 コマ流れた(シード 1)。ControlNet は深度 1.0 でも 2〜3 コマ行き過ぎ(止まったあと 11px/コマ)、骨だけ・両方・0.6 は 5 コマ前後行き過ぎて、止めの間もカメラが動く(骨 0.6 は止めの残り 45%)。骨には背景の手がかりが無いので当然の結果。
- **回りこみ(カット 3)**: Ref2V A・B は相関 0.93。止まりはシード 1 が 0 コマ、シード 2 が +3 コマ。ControlNet 両方は +5 コマ。
- **メモリ**: H3 の実行中、空きは 33〜36GB まで下がった(40GB の決まりを割った。ComfyUI がモデルを持ったままの分 + H3 のピーク)。落ちた処理は無い。

## 目で見た結果(連続コマのシートと切り出し)

- 衣装: 星柄 B の 34 本は、連続コマのシート(全本)と等倍の切り出し(約 15 本)で見た範囲で設定画どおり(ケープ・金の縁・帯の結び・フリルの下スカート・黒い袖)。**手本 A のパーカー・短パン・ブーツは 1 本も残らなかった**。灰色の体・棒の線・骨の色も人物には出ていない。
- 手本 A の見た目が出たのは 1 か所: パーカー + 手本 A のカット 2 の後ろ姿(設定画に後ろ姿が無い)。3D モデルの後ろ姿(髪の束の形・パーカーの背中の模様・足の影)がそのまま出た。
- 背景: Ref2V は手本の箱・柵・床の継ぎ目・人物の影の向きまで写す(3D の仮の箱がコンクリートの建物になって残る)。A・B・C で差は小さい。ControlNet の深度は箱と柵の位置を保ったまま絵にする。骨だけは柵がガラス張りになるなど、場面が文しだいで、カメラが回っても背景がついてこない。
- 髪: 正面では全条件で「下ろした長い髪 + 頭の上の房とリボン」に見える(設定画の正面がそう見える絵のため)。後ろ姿・横では太いポニーテールとして出た。カット 3 の ControlNet 両方(シード 1)は横でも下ろし髪に近い。
- 手: 振り上げた手は、Ref2V の A・B で**細い板のような手**(手本のミトン・閉じた手を写した)、C と ControlNet では指の開いた手。
- 顔・前髪: 引きの絵(顔の幅 60〜90px)の範囲では崩れは見えない。**2 倍に拡大した前髪・目の点検はしていない**。
- 人物の大きさ: Ref2V は手本より頭が大きく頭身が低い(設定画の頭身に寄る)。足もとの位置は手本と同じ。

## MAD の速いカットに使うときの見立て

1. 体の決めポーズを拍に当てるカットは、マネキンの骨を ControlNet に(1.0。背景も縛りたければ 深度 0.3 を足す)。設定画は Picture で渡す。0.6 に下げない。
2. カメラが主役のカット(振り・回りこみ)は、灰色人形 + 舞台の箱を `<Video 1>` に。素体モデル(VRM)でも同じ精度だが、設定画に無い向きで 3D の見た目が出るので、**灰色人形のほうが安全**。棒人形はカメラに弱い。
3. Ref2V は 1〜2 コマ先走るので、手本のキーを 1〜2 コマ遅らせるか、置くときに 1〜2 コマずらす(T1 の範囲。T3 でまた変わる可能性あり)。
4. Ref2V は背景も写すので、舞台を作りこむほど背景は決まるが、箱のままだと箱の建物になる。背景を H3 に任せたいカットは ControlNet(骨)。
5. 124 コマが下限なので、1〜3 秒のカットは「124 コマに出来事を並べて作り、切り出す」形になる。今回の 3 回の振り・4 回の腕は 1 本の中でどれも手本の時刻に乗った。

## 確かめていない事・推測のままの事

- T3(本番の段数)では未確認。ControlNet の「2 コマ打ち」「カメラの行き過ぎ」が T3 でも同じかは分からない。
- ControlNet + 参照動画(`<Video 1>`)の同時使用は試していない(今回の M2 は設定画だけ)。カメラは Ref2V・体は骨、の合わせ技が効くかは未確認。
- ControlNet の `end_percent`(途中で外す)・強さ 0.8 は試していない。深度だけの強さ 1.0 でカメラが 2〜3 コマ遅れる原因(速い振りのぼけを H3 が減速として描く、と推測)は確かめていない。
- 手本の速い振り(1 コマ 50px 超)は測定(DIS フロー)が追い切れていない。カット 2・3 の「山の高さの比」は当てにならない。止まるコマとずれは当てになる(手本どうしで 0 コマ)。
- 骨の映像は 3D の筒で描いた(本物の OpenPose 前処理の出力は一定の太さの 2D の線)。後ろ姿では鼻・目の点を切り、耳だけ残した。この違いの影響は測っていない。
- 灰色人形は髪なし・スカートなしの素体。ポニーテール付きの人形にしたらどうなるかは試していない。
- 顔・前髪・指輪など細部の 2 倍点検、音つきで見た気持ちよさの評価(人の目)はしていない。
- Codex の調査が挙げたジャンプと着地のカットは作っていない(マネキンのキーで作れるが本数の都合で外した)。
